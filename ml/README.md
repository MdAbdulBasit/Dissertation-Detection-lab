Generated by `scripts/triage_model.py`. Raw numbers in `triage_results.csv`.

pip install scikit-learn --break-system-packages

## The question

The Navigator result measured that **37 engineered rules closed every coverage gap and added no
discriminating power** — one genuinely discriminating detection before, one after. Rule engineering
solves coverage; it does not solve discrimination.

So: can a classifier separate attack from benign **from the same telemetry**, where rule logic cannot?

**A high score here is the failure case.** The easiest way to get one is to learn the lab's own habits.

## Data

| | |
|---|---|
| In-window alerts | 2,683 — 1,919 attack / 764 benign |
| Grouping unit | **259 detonation windows** (median 8 alerts each, max 58) |
| Techniques | 15 |
| Majority-class baseline | accuracy 0.715, **macro F1 ≈ 0.42** |

Alerts inside one window share command lines almost exactly, so a random alert-level split would put
near-duplicates on both sides. Two grouped splits are used instead:

- **GroupKFold on `session_id`** — no window spans train and test. Realistic evaluation.
- **LeaveOneTechniqueOut** — train on 14 techniques, test on the 15th. Tests whether anything transfers.

## What this means

**1. Within known techniques the model clearly beats rule logic.** Macro F1 **0.784 without rule
identity**, against a 0.42 majority baseline — and against a ruleset that, measured on the same data,
discriminates on exactly one technique out of fifteen. Attack precision of 0.958 at 0.755 recall is an
operationally useful trade: it would suppress most benign alerts while keeping three-quarters of real
detections.

**2. Removing rule identity costs almost nothing** — 0.823 → 0.784. This was the main worry, because
`92052` alone is 359 attack / 2 benign and a model could have scored well by memorising it. It didn't
need to.

**3. It does not generalise to an unseen technique.** Macro F1 collapses to ~0.54, benign F1 to ~0.37.
The model learns the command patterns of techniques it has seen, not a transferable notion of
maliciousness. **For a SOC this is the important limitation**: it would help with known techniques and
offer little against a novel one — the same weakness as the rules it is meant to supplement, arrived at
from the opposite direction.

**4. The benign class is always the weaker one** — precision 0.56–0.67 even in the best case. Benign
alerts are the operationally expensive ones, so this is where the remaining error lives.

## ⚠️ Three layers of leakage had to be removed, and each looked like signal

This is the most transferable finding in the chapter.

**Layer 1 — names.** 18% of alerts carried a token that gave the class away: `atomic` (127/0),
`deleteme` (64/0), `T1xxx` (231/5), `lab…` (0/203), and **`benign` (0/138)** — the class name, literally
in the command lines, because the mirror names its artefacts `LabBenignSvc`, `labfetch`, `labstale.bat`.
Those names exist to make the lab auditable. Untreated, the model scores ~95% and has learned nothing.

**Layer 2 — habits.** After stripping names, the top features became `noprofile command` (2.1% attack),
`exe noprofile` (18.5%), and `calc exe` (**100%** attack). None of that is attacker-versus-administrator:
`-NoProfile -Command` is how **my own** `Invoke-ViaPowerShell` helper invokes PowerShell, and `calc.exe`
versus `notepad.exe` is ART's choice of demo payload versus mine. The model was recognising **who wrote
the command**, not what it did.

**Layer 3 — the placeholder itself.** Substituting `HARNESSFLAG` did not fix layer 2 — it renamed it.
The marker stayed a top feature at 11% attack, because only one class ever emitted the thing being
substituted. **A placeholder does not sanitise a token that only one class produces.** The tokens had to
be deleted outright, which also destroys some genuine information — an attacker really might use
`-EncodedCommand`. That cost is accepted and it biases *against* the model, which is the safe direction.

> Each layer looked like real telemetry. Each was found only by reading feature importances and asking
> why a plausible-looking token was 0% or 100% of one class. **A leak that survives is indistinguishable
> from a good result.**

## Honest limitations

- **259 windows is the real sample size**, not 2,683 alerts.
- One endpoint, one OS build, one operator's command style.
- The benign mirror is *designed* to resemble the attack; a production benign distribution is far wider
  and messier, so real-world precision would be lower.
- Deleting harness tokens removed some legitimate signal along with the leak.
- No hyperparameter search — a single Random Forest, deliberately, since the comparison between feature
  sets is the experiment rather than peak performance.
